Testing Strategy: Cloudflare Tunnel vs. Local Simulation

Since our target production runtime is Cloudflare Workers and Cloudflare Pages, how should we test locally? Here is the recommended multi-tier approach:

Tier 1: Pure Local Edge
Directly executes unit/integration tests and local dev servers (Node/workerd emulation) with zero internet connection.
  • Instant feedback (<1s test cycles).
  • No external dependencies or accounts.
  • 100% private: no data leaves your machine.
  • Runs POS offline IndexedDB tests.
Tier 2: Cloudflare Tunnel Best for Gateways & Kitesurf
Temporarily exposes your local port (e.g. 4330) over a secure, outbound-only Cloudflare Tunnel (cloudflared).
  • Live Inbound Webhooks: Paystack & PalPluss sandboxes post callbacks directly to your local server.
  • Cloudflare Kitesurf & Browser Run: Cloudflare edge browser isolates can connect directly to your tunneled URL.
  • Zero open firewall ports; instant teardown.
Tier 3: Preview Worker
Deploys to an isolated Cloudflare preview subdomain (e.g. preview.nondies.workers.dev) with disposable preview D1/KV bindings.
  • Final gate before handoff.
  • Strictly isolated from live apex/www routes.
  • Validates Cloudflare image resizing & edge cache headers.
Strict Safety Rule: Never deploy to production or run commands targeting apex/www routes or live Nondies KV/D1 databases. All local and tunnel testing operates strictly on preview configurations.

Module 5: Cloudflare Tunnel, Inbound Webhooks & Kitesurf / Browser Run

How to connect Cloudflare's serverless browser isolates (Kitesurf) and live sandbox webhooks to your local dev environment.

16
Start Cloudflare Quick Tunnel

With your local frontend running on port 4330, open a second terminal and start a temporary, authenticated-free quick tunnel:

Terminal (Second Tab) 
cloudflared tunnel --url http://localhost:4330

Copy the resulting HTTPS URL output (e.g. https://nondies-local-random.trycloudflare.com).

17
Run Automated Audit via Kitesurf / Browser Run

Use Cloudflare's Browser Run API with the ?browser=kitesurf flag to capture an edge screenshot and verify SSR isolate compatibility:

Terminal (API Execution) 
curl -X POST "https://api.cloudflare.com/client/v4/accounts/$CF_ACCOUNT_ID/browser-run/screenshot?browser=kitesurf" \
  -H "Authorization: Bearer $CF_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://nondies-local-random.trycloudflare.com/fixtures"}' \
  --output "kitesurf_fixtures_audit.png"

Alternatively, open the Cloudflare Kitesurf Playground and paste your tunneled URL to inspect DOM tree rendering and WebAssembly isolate memory footprint.
